## أ. الجلسات

### أ1. حقائق الباك إند

| الحقيقة                                                                                                  | المصدر                                  |
| -------------------------------------------------------------------------------------------------------- | --------------------------------------- |
| login وrefresh يرجعان `{ accessToken, refreshToken }` في الـ body                                        | `AuthController`, `AdminAuthController` |
| access افتراضيًا `15m`، وrefresh `30d`                                                                   | `env.schema.ts`                         |
| سجل refresh واحد لكل `userId`                                                                            | `MongooseRefreshTokenRepository.save`   |
| التدوير ذرّي: من طلبين متزامنين ينجح واحد ويفشل الآخر بـ `401 INVALID_TOKEN`، والجلسة في الباك إند سليمة | `rotate()`                              |
| الدخول من جهاز آخر يُبطل refresh القديم، وaccess القديم يبقى صالحًا حتى ينتهي                            | لا قائمة إبطال                          |
| لا endpoint خروج                                                                                         | —                                       |
| الباك إند يقبل `x-request-id` الوارد ويعيده                                                              | `RequestContextMiddleware`              |

### أ2. التخزين والفصل

- cookie واحد مختوم (iron-session): `__Host-admin_session` في الإنتاج و`admin_session` محليًا. `HttpOnly`، و`Secure` في الإنتاج، و`SameSite=Lax`، و`Path=/`.
- المحتوى: `sid`، و`accessToken`، و`refreshToken`، و`accessExp`، و`subject { id, role }`.
- سر ختم مستقل لكل تطبيق. BFF الأدمن يرفض أي جلسة `role !== 'admin'`.

### أ3. واجهة الـ BFF

| Method                | Path                                                  | الوظيفة                    |
| --------------------- | ----------------------------------------------------- | -------------------------- |
| POST                  | `/bff/session`                                        | دخول (`/auth/admin/login`) |
| GET                   | `/bff/session`                                        | الحالة والهوية             |
| DELETE                | `/bff/session`                                        | خروج من هذا المتصفح        |
| GET/POST/PATCH/DELETE | `/bff/api/countries[/{id}]`, `/bff/api/cities[/{id}]` | proxy مقيّد                |

**تصحيح تعارض الـ allowlist:** الـ proxy يقبل countries وcities فقط. اسم الأدمن وبريده يجلبهما `GET /bff/session` **داخليًا** من `GET /admins/{subject.id}`، حيث `id` مأخوذ من الجلسة المختومة وليس من المتصفح. لا يوجد مسار عام إلى `/admins`.

### أ4. التجديد

1. **استباقي:** إذا بقي على `accessExp` أقل من 30 ثانية.
2. **التنسيق:** داخل نسخة السيرفر الواحدة. تجديد واحد لكل `sid` في وقت واحد، وتُحفظ النتيجة **30 ثانية** تحت `sid + sha256(oldRefreshToken)`. **هذه نافذة لمعالجة الطلبات المتأخرة التي تحمل الـ cookie القديم، وليست ضمانًا لكل حالات انقطاع الشبكة.**
3. **سياسة الفشل:**

| رد الباك إند على التجديد                           | التصنيف       | السلوك                                                                            |
| -------------------------------------------------- | ------------- | --------------------------------------------------------------------------------- |
| `200` بتوكنات صالحة                                | `rotated`     | تحديث الـ cookie                                                                  |
| `401` وتوجد نتيجة أحدث للجلسة نفسها                | —             | استخدامها. لا مسح                                                                 |
| `401` ولا نتيجة أحدث                               | `rejected`    | **الحالة الوحيدة التي تنهي الجلسة:** `SESSION_EXPIRED` وحذف الـ cookie            |
| `429`، `5xx`، شبكة، timeout                        | `unavailable` | **لا مسح.** `503 SESSION_REFRESH_UNAVAILABLE` مع `Retry-After` إن أرسله الباك إند |
| أي رد آخر (`400`، `403`، `404`، `200` بلا توكنات…) | `failed`      | **لا مسح.** `502` بخطأ خادم عام (بلا نص من السيرفر)، مع `requestId`               |

**Retry-After:** يُقرأ كثوانٍ أو كتاريخ HTTP، وبحد أقصى 300 ثانية. حتى ينقضي، لا يحاول الـ coordinator أي تجديد جديد لنفس الجلسة، بل يرجع `unavailable` بالوقت المتبقي. والواجهة لا تعيد المحاولة تلقائيًا في هذه الحالة، بل يقرر المستخدم.

4. **إعادة الطلب:**
   - تُعاد مرة واحدة فقط بعد **`401` مؤكد من حارس المصادقة**: `INVALID_TOKEN` أو `errors.UNAUTHORIZED` على endpoint محمي. وهذا يشمل طلبات الكتابة.
   - **لا إعادة تلقائية بعد timeout أو خطأ شبكة**، لأن الطلب ربما نُفّذ فعلًا. الواجهة تعرض الخطأ وتترك القرار للمستخدم، والمستخدم يرى القائمة محدّثة قبل إعادة المحاولة.
   - لا تجديد أثناء الدخول، و`401` بعد تجديد ناجح ← `SESSION_EXPIRED`.
5. **الخروج أثناء تجديد جارٍ:** `DELETE /bff/session` يُلغي `sid` في الـ coordinator (tombstone) ويمسح نتائجه. أي طلب جارٍ يتحقق من الإلغاء **مرتين**: قبل تشفير الـ cookie، ثم **بعد انتهاء التشفير ومباشرة قبل `Set-Cookie` دون أي `await` بينهما** (التشفير غير متزامن، وقد يحدث الخروج أثناءه). إذا كان ملغى، لا يُكتب cookie ويرجع `401 SESSION_EXPIRED`. وأي طلب لاحق يحمل `sid` ملغى يُرفض.
6. **قراءة الرد جزء من الطلب:** انقطاع الاتصال أو انتهاء المهلة أثناء قراءة جسم الرد (بعد وصول الـ headers) يُصنَّف `network`/`timeout` مثل فشل الإرسال تمامًا، ولا يُعاد الطلب.
7. **حد موثَّق — ضياع استجابة التدوير:** إذا نجح التدوير في الباك إند وضاعت استجابته (انقطاع بين الـ BFF والباك إند)، يصبح refresh token في الـ cookie غير صالح، ولا يحتفظ الباك إند بالتوكن الجديد بشكل يمكن استرجاعه. **بالعقد الحالي قد يتعذر استرجاع الجلسة**، وينتهي الأمر بـ `SESSION_EXPIRED` عند المحاولة التالية. الحل يحتاج دعمًا من الباك إند (مثل فترة سماح للتوكن السابق أو idempotency key للتدوير).

### أ5. الخروج

- النص: **«تسجيل الخروج من هذا المتصفح»**.
- لا تذكر الواجهة أنه يُلغي كل الأجهزة أو يُبطل التوكن على السيرفر.

### أ6. CSRF (لكل طلب `/bff/*` غير `GET/HEAD`)

1. إذا وُجد `Origin`: يجب أن يطابق **`APP_ORIGIN` المضبوط في إعدادات التطبيق** تمامًا، وإلا يُرفض **حتى لو وُجد header آخر يسمح**.
2. إذا غاب `Origin`: يُقبل فقط إذا كان `Sec-Fetch-Site: same-origin`.
3. غياب الدليلين ← رفض.
4. `Content-Type: application/json` مطلوب فقط للطلبات التي تحمل body. `DELETE /bff/session` بلا body لا يحتاجه.
5. الرفض: `403` بكود `security.CSRF_REJECTED`.

لا تُشتق القيمة المقارَنة من `Host` أو `X-Forwarded-*`.

## ب. الأخطاء

```ts
interface AppError {
  kind:
    | 'validation'
    | 'invalid_credentials'
    | 'session_expired'
    | 'forbidden'
    | 'not_found'
    | 'conflict'
    | 'csrf'
    | 'rate_limited'
    | 'server'
    | 'session_refresh_unavailable'
    | 'network'
    | 'timeout'
    | 'unknown';
  status?: number;
  formErrors: { code: string; serverMessage?: string }[]; // كل الأخطاء العامة، وليس كودًا واحدًا
  fieldErrors: Record<string, { code: string; serverMessage?: string }[]>;
  requestId?: string;
}
```

- **كل الأخطاء العامة تُحفظ** في `formErrors`، لأن الرد قد يحتوي عدة أخطاء دون حقول.
- **الدخول استثناء:** `401 INVALID_CREDENTIALS` يُعرض داخل نموذج الدخول (`kind: 'invalid_credentials'`)، ولا يتحول إلى `SESSION_EXPIRED`.
- **`5xx` والردود غير المتوقعة:** رسالة عامة مترجمة فقط، **دون عرض نص السيرفر**. `serverMessage` لا يُحفظ لهذه الحالات.
- **`requestId`:** الـ BFF يولّد UUID لكل طلب ويمرره للباك إند في `x-request-id`، ويضعه في أخطائه المحلية (CSRF، الشبكة، `503`). ويُعرض للمستخدم قابلًا للنسخ.
- النص المعروض: كتالوجنا حسب `code`، ثم `serverMessage` (لأخطاء 4xx فقط)، ثم رسالة عامة حسب `kind`.
- بدون optimistic updates.
